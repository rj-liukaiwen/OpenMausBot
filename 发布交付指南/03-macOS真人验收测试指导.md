# 锐捷 Bot：macOS 真人验收测试指导

对象是最终安装的 Bot `.app`，不是源码版，也不是 Harness。
验收记录应包含 desktop-build.json 关联的源码指纹和实际包内 UI/server 摘要；
开发预览共用构建内容，但账号、缓存、浏览器配置仍须隔离，不能借开发环境的已有登录通过。
配合本目录 Mac 打包指南及签名策略；默认不授权卸载、覆盖应用、清理真实用户数据或 TCC。
测试安装/升级、登录、系统权限应由获得授权的测试者在专用账户中完成。

> 2026-09-11：Windows 开发版已获用户确认；Mac 飞书、浏览器和权限仍须在本平台独立验收。
> Mac 许可工程复核和相关源码测试已有记录，不代替签名后运行/授权；新增屏幕录制重复授权专项。
> 插件服务可要求 VPN/代理，但离线首启后开启系统代理并点击重试必须恢复连接入口；
> 注册、授权、列表和只读调用都要测，不能用重装、清缓存或只看图标代替。Mac 飞书须确认界面不再误报仅支持 Windows。
> 共用要求见 [通用回归与发布门禁](04-通用回归与发布门禁.md)，不能继承 Windows 的通过结论。

## 1. 固定对象与证据

记录 Bot 版本、完整源码 SHA、DMG SHA-256、架构、macOS 版本、签名/公证状态、
Harness 安装版本（接口基线 2.1.6）、是否升级测试，以及网络/容器条件。
当前代码基线 0.1.73；不能拿 Harness 版本号当 Bot 版本号。

只从 `WYunS/OpenMausBot` 的 main 固定 SHA 对应的候选 DMG 开始，和 Windows 使用同一 SHA。
每项记录：预期、步骤、实际、截图/脱敏日志、
通过/失败/环境阻塞/未执行。视频、日志里隐藏账号、额度细节、邮箱、token 和私人对话。
测试 Bot 和网页使用可识别的临时名称，不删除日常真实 Bot。

## 2. 安装、启动与权限基线

1. 挂载最终 DMG，核验签名、Bundle ID `com.openmausbot.app` 和目标架构；
   安装到测试账户选定的 Applications，从安装版启动，确认不依赖检出目录或 Node/pnpm。
2. 窗口为锐捷Bot，登录页不是旧 OpenMausBot 文案；启动出现 RJ/加载反馈，不出现
   无解释的长黑屏。记录冷启动、登录各阶段时间，不以“某台机器快”代替多次结果。
3. 没有操作时不弹 Harness GUI、目录选择器或访问屏幕的系统授权。
   在 Bot 普通打开与关闭时，Harness 均不应被无故拉起。
4. 主动使用“这台电脑”才由人授予所需辅助功能/屏幕录制权限；允许后截图有真实画面，
   鼠标键盘操作有效，拒绝/取消时有可读说明，不进入持续弹窗或工具重试循环。
5. 受保护目录访问按签名策略测试；同一安装版本同一动作不能反复 Allow。
6. 关闭应用后进程安全收尾；再次启动数据保持，无第二个服务抢同一数据目录。
7. Finder、DMG、Dock 图标均为产品图标，不出现 Electron 原子；开发版图标不作为此项替代证据。

### 2.1 屏幕录制重复授权专项（必测）

前提：专用获授权测试账户，候选从 DMG 安装到固定 Applications 路径；不从 DMG、下载目录、
源码 Electron 或另一份旧 App 同时运行。记录应用路径、macOS 版本、架构、签名类型/Team ID、
`codesign -dr -` 输出及 CUA 实际 embedded/standalone 模式，命令见关联签名策略第 5.1 节。

1. 无操作冷启动不主动弹屏幕录制授权；首次主动使用电脑功能时由人授权，按系统要求重启后能截图。
2. 同一版本连续截图/接管三次、停用再启用三次，不重复申请已经授予的同一权限。
3. 完全退出并重开三次，每次实际截图；条件允许再注销/重启测试账户后复测，授权仍能被识别。
4. 在独立测试场景拒绝/取消一次：停止请求并说明原因，不自动循环；用户在系统设置更正并
   主动重试后可恢复。不得自动点击系统许可、重置全局 TCC 或要求全盘访问来代替屏幕录制权限。
5. 获授权后按同一路径覆盖升级旧安装版，核对主 App/Helper/CUA 的 requirement 和实际身份。
   Developer ID 正式路线不接受因每次构建随意改身份导致的重复申请；ad-hoc 若升级需重新授权，
   如实记录并完成新的同版稳定性复测，不把它宣传为正式签名的权限持久性保证。
6. 区分 macOS 自身的周期性权限复核和每次操作的循环，记录完整弹窗原文、时间间隔；
   未确定原因前不归咎签名、VPN，也不把系统复核当产品已修复。任意无界重试均为失败。

GitHub Actions 的绿灯不是本项通过记录；用户本地 Windows 结果也不覆盖该项。

## 3. Harness / 模型 / 统一档位

新增必测：分别用已支持的 CLI/Harness 发普通问题、触发英文工具输出再让它总结，
面向用户的进度/结果默认中文；代码、路径和工具名保持准确，不翻译命令。
单聊、群组、续聊都需覆盖；用户明确要求英文时才按要求切换。工作目录/私有记忆路径不漂移。
浏览器被后台暂停或网络短断后最多自动重连画面三次，不自动夺回接管权限、不重放操作；
旧视图关闭后不得再污染新视图。凭据更新后说“继续”应保留此前任务上下文。

1. Harness 未安装时显示准确安装指引；已安装但未运行时模型入口可用、显示按需启动，
   不以“需要设置/当前未运行”误挡模型列表。未连接不能假装已登录或有余额。
2. 先普通打开 Bot，再主动刷新 Harness 模型/发消息，测试并发状态探测与主动启动。
   发现的是本机正式安装版，不是打包者电脑上的源码路径。后台桥接不得弹主窗口。
3. 使用本人测试账号登录，确认调用读取该 Harness/GPTAuth 账号的权益，不读取别人的缓存。
   未登录/额度不足/网络失败要准确说明，不重置已有 Bot 或插件授权。
4. 新 Bot 默认 `DeepSeek-V4-Flash / low`。固定 Bot 推理档
   none/low/medium/high/xhigh/max 不随模型换一套；后台映射到该模型合法档位。
   模型顺序应遵循已封装目录（GPT 6、Sol、Terra、Luna、5.5；新目录变化按交付差异核对）。
5. DeepSeek、Claude、GPT 每类至少验证一个模型；轮流选择固定档位发送无害请求，
   不得因档位不支持报错。图片场景使用视觉模型，两个 DeepSeek 非视觉模型不可被误派图。
6. 发送问候后记录首次内容与完成时间；比较同网络/模型/档位多次结果，不能把固定 30 秒
   无内容等待说成正常，也不以官方网页 5 秒就推断所有模型 CLI 必须 5 秒。

## 4. “这台电脑”与浏览器分别验收

两者不是同一功能，不要因浏览器成功就给桌面工具打勾。
浏览器必须测两种顺序：先打开面板再让机器人搜索，以及先搜索再打开面板。
每种顺序连续观察至少 60 秒，接管、导航、交还、再搜索连续做三轮；原画面连接不得被重启，
不能以自动重连成功或一张不更新的旧图判定通过。细则与自动检查见通用指南第 2 节。

- “没有电脑”：问候正常回复。
- “这台电脑”：测试者打开临时文本编辑窗口，让 Bot 截图并输入一句无害文字；
  检查真实工具执行，不出现 preset/schema 挂载错误、stderr 关闭导致代理退出或假成功。
- 浏览器：开启对应权限后出现 BrowserPanel。普通查看为只读；接管后可打开当前网络
  可达网址/本地夹具、输入、点击、Enter；交还之后 Bot 可继续使用。
- 全新安装 profile 中浏览器应默认开启；用户曾明确关闭的 profile 仍保持关闭。
- 同一个右上角全屏按钮能进入/退出，不必 Esc。刷新外层面板后保留网页并能重新接管。
- 地址不可达或服务不响应时显示准确网络错误，完成取消后仍能换网址，不永久提示
  “另一窗口或 Bot 占用”；真正未知中断可通过显式重启恢复，不无声放开操作锁。
- 两个查看窗口争用同一 profile 时只有一方能接管；不能以修复锁为理由让双方同时操作。
- 无外网测试用本地页面，不要求 Google 可达；内置浏览器不是系统 Google Chrome。

有源码工具的验收者可使用 `docs/verification/browser-live.md` 的隔离测试：
`verify-browser-live-control.ts` 包含永不返回 headers 的本地 `/slow` 和恢复后的真实输入验证。
它是辅助证据，仍需对安装包所带 native engine 运行 smoke 并在安装版中操作。

## 5. 删除、归档、插件与数据

1. 新建临时 Bot，创建几条测试消息，取消一次删除确认，再实际确认删除。
2. 关联离线 VPS/Box/容器的临时 Bot 仍能本地删除，不要求先连电脑。
   界面只显示正在删除；确认文案说明独立电脑未删除、可能继续运行或计费。
   活跃任务/电脑创建/凭据保存仍有保护，先结束再删；勿把这些安全互斥当离线连通性检查。
3. 刷新并重启确认临时 Bot 已消失、其他 Bot 不变。远程遗留资源归属应保留；
   Local VM vm-homes 不随 Bot 删除，目前不能据此保证已删除 VM 都出现在独立管理列表。
4. 归档 Bot 从主列表移走，在“工具 → 已归档”可找到并恢复，消息保留。
5. 原生插件品牌图标有显示；使用已授权测试连接验证刷新/重启保持，不无故丢 Gmail。
   第三方离线时缓存图标和已知状态可显示，但不能谎报连接健康。
6. macOS 飞书适配代码已补齐，原生/签名后与真实账号验收仍是必测，不能按“不适用”跳过。
   对照 [通用回归与发布门禁](04-通用回归与发布门禁.md)，使用授权测试账号
   验证首次连接、IM、工具读取、重启恢复；没有 Mac 或账号写“环境阻塞”。
   首次连接不借用 PATH/Homebrew 的 CLI/Node，不临时下载另一版；升级不能丢现有授权。
7. 打开设置页并在普通窗口尺寸和缩放下点击右上角关闭按钮；按钮应保持 40×40 点击区域、
   不被标题挤压或遮挡，并能一次关闭。该项是共用 UI 修复，不能只用 Windows 结果代替。
8. Local VM/远程电脑按真实环境验证；未安装 Podman 或无远端权限不属于“已通过”。
   不能下载未知镜像、关闭系统安全或清除所有容器来强行通过。
9. 云应用须完成离线首启→恢复网络/系统代理→点击重试→授权→一次只读调用→重启仍可用。
   `CONNECTED_APPS_NETWORK_UNREACHABLE` 是请求异常归类，不是 VPN 根因证据；`expired`
   与网络故障分别记录，缓存列表/绿色图标不作为实时健康证明。飞书原生通道另测，不能互相替代。

## 6. 升级与更新源

- 仅对获授权的旧**安装版**测试账户覆盖升级；提前记录测试 Bot、连接器、授权、历史。
- 不复制开发版加密凭据到安装版。安装版服务数据在当前用户主目录的
  `~/.ruijiebot`，开发版仍使用 `~/.openmausbot`；Electron 自身缓存按 macOS 规则
  位于用户的 Application Support 下。不得合并、覆盖或复制开发版数据。
- 新版本保留安装版自己的数据、设置、连接与账号状态；必要重新授权应解释原因。
- 检查包内 app-update.yml 的 owner=WYunS、repo=OpenMausBot。不要在线发布新版本来
  验证更新；只有发布负责人另行授权且已有完整资产时才执行真实更新。
- Developer ID 路线验公证与 Gatekeeper；ad-hoc 路线如实记录首次启动和每次升级提示，
  不承诺跨版本永远零授权。不得清除 quarantine 或重置 TCC 掩盖循环。

## 7. 放行、断点与报告

报告首段写：验收对象、通过/失败/阻塞/未执行数量、**允许进入下一步**或**阻断**。
源码回归通过仅允许打候选，不自动允许正式上线。核心启动/登录/工具不可用、
数据损坏/丢失、安全问题、签名不完整或反复权限弹窗必须阻断。
低影响瑕疵可由负责人有条件放行，必须写明影响、规避方式和未测项，不写“全部通过”。

遇非破坏性失败先收集证据并继续独立项目；若继续会破坏数据或污染结果则停止。
验收者不要悄悄修产品再沿用同一候选哈希。源码/依赖/配置变化后是新候选；
只有验收器定位修正且 DMG 字节未变时，才可从有证据的最近可信断点续跑。
每次验收结束审查本指南，仅把已证实的新规则纳入固定基线，不把一次网络抖动写成永久产品限制。
