# 锐捷Bot：通用回归与发布门禁

适用于 Windows x64、macOS arm64/x64 的每一版，不是本次问题的临时备注。
规则：先复现 → 锁定源码/运行时 → 修复 → 同一复现复测 → 原生验收 → 生成候选 → 安装验收。
构建退出码 0、类型检查、图标出现、HTTP 401 都不能单独证明插件可用。
“未执行 / 阻塞 / 跳过”不是通过，不允许以“源码共用”继承另一个平台的结论。

源码交付入口为 **WYunS/OpenMausBot 的 main**；打包固定完整 SHA，Win/Mac 使用同一提交。
此前的 `codex/openmaus-upgrade-0.1.71-ready` 是修复分支，作者的 origin/main 不是本产品交付源。
Release 已限制为手动入口，main 推送不触发安装器；Docker 分支任务只构建/检查，不发布镜像。
手动 Release 仍含上游镜像/资产规则，未另行审查和授权前不要运行。同步源码不等于发布产品。

用户已确认当前 Windows 本地开发版测试无异常、飞书可用；保留已正常的飞书实现和账号。
这不是新安装器、Mac 或每种第三方应用的完整通过凭据。原始过程与最后有效结果见

## 1. 先核实测的是谁

### 本地开发快捷方式与安装包保持同一构建内容

“锐捷Bot（本地开发版）”快捷方式使用 `OMB_DESKTOP_PREVIEW=1`，启动前运行
`prepare-local-preview.mjs`，校验源码/产物指纹并按需重建；加载同一 `dist`、`dist-server`、
正常 staging 的 browser 与 feishu-runtime。不再用 Vite 热更新或本机 PATH 成功代替包内行为。
普通 `pnpm dev` 仍可用于开发，但不是交付验收入口。

`dist-native/desktop-build.json` 绑定源码指纹与 UI/server 文件树摘要。
`package:prepare` 产生同格式记录；beforePack 验当前源码和构建，afterPack 再验实际复制到包内的 UI/server。
缺失、源码变化、旧 dist 混入或文件被改都会停止，不允许手写指纹掩盖未构建。
先验收本地开发预览，再允许生成候选安装包。放行记录必须包含
`desktop-preview-acceptance` 的实际验收证据，并把已验收的 `desktop-build.json`
中的 `ui`、`server` 摘要记录在放行 JSON 的 `desktopBuild` 对象中。
即使源码指纹没变，重建后任一文件树摘要改变，也必须重新验收，不能把“同源码”当“同产物”。
源码变更后须完全退出本地开发版，再从该快捷方式启动；运行中任务不会被脚本强制中断。

“同一构建”不等于共享状态：开发/安装仍分别使用开发身份与安装身份、独立端口、
`.openmausbot` / `.ruijiebot` 和独立 Electron userData。不要复制账号凭据或浏览器 cookie。
Mac 签名/TCC、第三方网络以及实际账号状态可能不同，仍须原生/安装后验收。

Windows 更新原生目录前退出本次开发前端；Vite 必须忽略 dist-native，避免目录监视占用使 rename EPERM。
浏览器 prepare 与 vendor 校验不得互相在顶层等待导入；CLI 子进程回归必须覆盖这一路径。
开发快捷方式还须覆盖 checkout 经 Windows junction/目录链接启动的情况：主进程仅将自己选择的
原生资源根目录解析到物理路径，再交给与安装版相同的严格运行时校验。不得关闭 no-junction 校验，
不得借此规范化任意用户配置/可执行文件；也不能因路径别名变更而清空授权或改写 MCP 所有权。
至少用临时 home 和实际固定 CLI/Node 通过 --version 准备流程，不能仅凭资源文件哈希或启动页放行。

开发快捷方式还必须验收慢启动时的重复点击：构建超过一分钟时，后续点击应合并到正在进行的
启动，不能弹出 `Another startup is still in progress`，不能启动第二份构建或结束第一份进程。
真正启动失败须先释放互斥锁再显示错误，未关闭的旧错误弹窗不能阻止用户重试。
运行 `node --test electron/local-windows-launcher-concurrency.node-test.mjs electron/local-windows-launcher.node-test.mjs`：
并发用例执行真实 Windows PowerShell 和生产锁控制代码，仅替换为独立锁名、测试动作和缩短的旧超时，
不启动/关闭用户应用。非 Windows 跳过不计为通过；此外仍需检查实际快捷方式冷启动与已运行窗口恢复。

- 记录完整 commit、dirty diff、版本、锁文件、配置和目标架构；开发快捷方式需解析真实目标。
- 使用 `node scripts/check-ruijie-release-readiness.mjs --fingerprint` 记录实际工作树指纹。
  该指纹包括未提交源码、测试、依赖补丁、public/build 静态资源、构建配置和指南，
  不只比较 package.json 版本。companion/enterprise/skills 变化同样必须重新验收。
- 所有操作在独立测试 home/dataDir 中完成，禁止借开发版账号、浏览器 cookie、缓存或 PATH 掩盖缺依赖。
- 安装版服务数据为当前用户 `~/.ruijiebot`，开发版为 `~/.openmausbot`；不用迁移旧测试包数据。
  Windows 的 AppData、macOS 的 Application Support/Logs 是 Electron 状态，不能与服务数据混称。

## 2. 浏览器：有功能还必须没有多余终端

共同检查：干净 profile 自动发现内置引擎和 Chromium、导航、真实输入/点击、截图、
两 Bot 隔离、同一 MCP 关闭再启动、接管/交还、网络取消后继续工作、窗口关闭按钮。
网络错误测试用本地正常页面、拒绝连接和不返回响应的夹具，不依赖 Google 是否能访问。
接入 Harness 等外部引擎时还要验证“模型操作的浏览器就是用户看到的浏览器”：
仅返回 Queued、等待另一个应用的侧栏连接，不能算导航成功；必须看到同一 Bot/session
的真实页面标题、画面及后续读取结果。至少持续观看 60 秒并覆盖切换窗口/后台恢复。
区分搜索 API 的免费额度耗尽、页面网络失败、画面流关闭、旧会话凭据失效；不能统一归因 VPN。
导航验收必须等待目标新文档可用，并确认顶部标签标题/地址同步，不以 `Page.navigate`
返回或画面像素改变作为全部成功。挂起文档必须有界取消，取消后仍能接管、输入和交还。
浏览器先由 MCP/搜索启动、后打开实时面板与面板先启动两种顺序都要测试；
MCP 空闲回收后，原画面流应保持连接，不能用自动重连掩盖被误关的原会话。
`scripts/verify-browser-runtime-lifecycle.ts` 必须分别运行默认顺序和 `--viewer-first`，
两者均执行三次真实人工接管/导航/交还/MCP 操作，再等待 MCP 空闲回收后的原流心跳。
界面、机器人 MCP 和截图入口必须共用相同的 daemon 启动配置，不能给查看入口单独注入
`AGENT_BROWSER_DEFAULT_TIMEOUT`：该值参与原生配置指纹，差异会触发 daemon 重启，
表现为搜索成功但右侧反复断开。命令超时应通过各操作的 deadline/watchdog 控制。
禁止在验收脚本中给工具端补上生产环境没有的参数来“对齐”，这会掩盖真正的配置差异。
再用 `scripts/verify-desktop-browser.mjs` 检查完整编译 UI/server + Electron utilityProcess +
真实 MCP 搜索，原 SSE 必须连续 60 秒，不能仅判断还有一张旧图片或自动重连后有图。
`scripts/verify-browser-stream-lifecycle.mjs` 另外检查真实面板导航、标签和后台 60 秒。
Windows 完整桌面脚本不代表 Mac 通过；Mac Actions 必须各自执行两种原生启动顺序，
签名安装版再按真人指南执行同样操作。源码修正、重新编译和最终安装验收是三个不同阶段。
运行后须重验所有发布文件。当前 Windows headless-shell 可能在自身目录写入 debug.log，
不能假设普通 Chrome 日志参数在它的子进程中同样生效。开发预览准备只允许在所有发布文件
仍逐项匹配时，把唯一额外的 `chrome/chrome-headless-shell-win64/debug.log` 普通文件归档到
`dist-native/browser-runtime-logs`，然后重新进行严格完整性检查；不允许加入正式清单、
忽略其他新增/修改文件，或为这一个日志重装整套组件。归档不是清缓存，不改用户账号。
Harness 模型钱包不等于联网搜索 API 额度。必须对比实际安装资源与源码的搜索顺序，
并检查真实配置下哪些引擎可用：把 Firecrawl 排最后不是禁用；用合成 key 验证排序也不证明用户可搜索。
锐捷Bot启用内置浏览器时，由自己的 agent preset 关闭原 tool-web 搜索/抓取，
加载独立 `harness-browser-tools` 模块，在该会话内把搜索、开页、读页映射到同一原生浏览器。
不得修改整个 Harness 的配置，不得在浏览器被人接管/取消后偷偷换入口或重试。
验收须包含无 Exa/Tavily key 的搜索、文章读取、来源 URL、无 Firecrawl 调用和其他 Harness 会话不受影响。
后台静态帧的 ACK 不得依赖暂停的动画回调；同时检查未解码图片不能提前 ACK，断开后不得仍显示“正在连接”。
读取错误日志必须对应本次 session/preset/tool 实例，旧会话残留的 unauthorized 重试不能当成本次根因。

```powershell
# Windows：在空闲、交互式桌面执行，不关闭用户现有窗口。
./scripts/verify-browser-no-console.ps1 -Resources '绝对路径/resources'
# 仅测试新依赖候选，不代表已经打包；候选需包含完整 provenance 和两份 patch。
./scripts/verify-browser-no-console.ps1 -Resources '绝对路径/resources' -EngineCandidate '绝对路径/agent-browser-win32-x64.exe'
```

必须同时看到 `fixtureExitCode: 0`、`ok: true`、`newVisibleConsoleWindows: []`。
其他软件新开终端会保守地导致失败；确认干扰后重测，不能直接忽略结果。
无交互桌面的 CI 不能证明“没有可见弹窗”；还要手工测试完整桌面版启用浏览器的操作。
10ms 轮询是回归辅助证据，不宣称能检测任意短暂窗口。

根因分类要追到实际创建窗口的进程：外层 Node 的 `windowsHide` 不会自动约束孙进程。
Windows headless-shell 是控制台程序；从 detached daemon 启动时，内部也必须用
`CREATE_NO_WINDOW`。不得用关闭 Chromium 沙箱、吞错误或启动后强行关窗代替修复。
依赖补丁改动必须产生新 vendor revision 和新 SHA；不能覆盖已发布的 `omb.1`。
当前生产 pin 已切换到专项原生测试过的 `.2` 精确字节，Windows 正式编译预览已完成真实 MCP、
三轮接管/刷新/交还和 60 秒原流复测；新 SHA、原生资源或安装包仍需重新绑定验收证据。
尚无已发布 `.2` URL：通过 `OMB_BROWSER_VENDOR_DIR` 或脚本默认本地候选目录提供
exe 与 provenance；缺失即停止，不能回落 `.1`。vendor 工作流的未审候选仅可生成
`win32-x64-candidate` 目录并带 candidate 标记，生产 afterPack 拒绝其清单。
画面短断只允许三次退避重连，不重放动作/恢复接管；关闭面板须清除重试定时器。

补丁命令退出码 0 也不是证据：临时源码可能位于用户另一个 Git 仓库内部，
`git apply` 会显示 `Skipped patch` 却成功退出。vendor 构建必须建立独立的临时 Git 边界，
检查实际仓库根目录、每份补丁反向校验以及最终源码版本/关键修复代码；不能只验 patch 文件 SHA。
临时仓库固定 LF 策略，不修改用户的全局 Git 设置。最终二进制还必须实跑 `--version` 和行为测试。

## 3. 插件：区分网络、服务和授权

1. 先只读探测服务，记录 DNS/连接超时/HTTP 状态，不输出 token。
   无凭据请求收到 401 只证明服务可达；超时不证明密钥错误，也不证明服务端宕机。
   `CONNECTED_APPS_NETWORK_UNREACHABLE` 是请求异常的归类，包含连接、代理、证书、重定向
   等可能性，不是“用户没开 VPN”的证明，也不能据此排除程序错误。`expired` 是账号授权状态，另查。
2. 分别验证直连、系统代理/PAC、代理关闭/端口失效、运行期间切换及恢复。
   VPN 开关不是检测结果：TUN 和系统代理模式不同，不能硬编码某个人的代理端口。
3. 桌面托管 Composio 的注册、catalog、OAuth、MCP 必须使用同一网络通道。
   当前通过私有 utility-process 通道委托 Electron Session 发送，禁止携带 renderer cookie，
   禁止重定向和任意上游 URL，只有父进程可以选择 broker 和注入凭据。
4. 首次离线后自动退避重试；恢复时保留原安装身份，不以清缓存、重装、反复创建账号解决。
   已有身份只有明确的 401 才能失效，临时网络错误不得删除它。
   “刷新/重试”必须立即触发本机注册重试并等待完成，不只刷新列表；并发点击共享同一次注册。
   已有凭据但列表 stale/error 时仍须强制刷新真实状态，不能不断续期失败缓存。
   验收覆盖：离线首启→开启系统代理→点击重试→连接入口恢复→授权→只读调用；
   再覆盖已连接→代理失效→恢复，不丢安装身份、不显示全部账号已断开、不要求重启或重装。
5. 服务可达后，使用明确授权的测试账号完成连接和一次只读工具调用，再测试刷新/重启。
   若拿不到账号或外网服务不可达，标为阻塞，不用模拟 HTTP 响应代替真实授权结论。

真实 Electron、私有 IPC、代理失效/恢复的离线回归：

```bash
node node_modules/electron/cli.js scripts/smoke-connected-apps-network.mjs
# 当前系统网络路径的只读外网检查（不注册、不携带任何账号凭据）：
node node_modules/electron/cli.js scripts/check-connected-apps-reachability.mjs
```

测试使用临时 Session、模拟 broker 和合成身份，不改用户代理，不创建外部安装记录。
Node 模块依赖已经存在时，若 PATH 的 pnpm 试图重装/清空 modules，立即停下，
改用锁定的 Corepack pnpm 或直接运行 `node node_modules/vitest/vitest.mjs run ...`。
不可为运行测试允许工具自动清空开发环境。

当前产品要求遵循各服务自身的网络条件：服务需要 VPN/代理时由用户提供，
不把自建服务或“所有插件无 VPN 可用”作为本轮交付要求。
软件必须使用已配置的系统网络通道，并允许网络恢复后重试；不能把软件的连接入口锁死归咎于 VPN。
未来若明确要求无 VPN 才另行评估可达服务及费用，本指南不授权部署。
禁止把共享项目 key/个人 VPN 配置/开发者 token 放进安装包，不能承诺任意网络永久可达。
上游公共 Worker 不是发行方自己的可用性保证；离线不应破坏聊天、浏览器和已知连接记录。
`RUIJIE_COMPOSIO_BROKER_URL` 是打包时的公开 HTTPS 地址设置，写入
`package.json` 的 `ruijieConnectedAppsBrokerUrl`；不是 Composio 项目 key。
放行记录的 `connectedAppsBrokerUrl` 必须与实际打包地址一致，防止测试 A 服务却发布 B 服务。

## 4. Mac 按功能补齐，不把缺功能改名为“通过”

| 功能 | 实现/差异 | 放行要求 |
|---|---|---|
| UI、关闭按钮、浏览器默认开启、数据隔离 | 共用源码 | Mac 原生 fixture 和最终安装复测 |
| 托管第三方插件网络 | 共用逻辑、Electron 系统网络栈 | Mac 代理恢复 + 实际 OAuth/只读调用 |
| 本机飞书 | Mac 桥、双架构运行时、资源与签名分支已补，隔离源码回归有记录 | 精确许可批准、双架构执行、签名后授权/IM/只读调用；未齐仍阻断 |
| 本机电脑控制 | Mac CUA 和辅助功能/屏幕录制权限 | 实机截图、输入、拒绝后恢复，不重置全局 TCC |
| 语音 | Swift helper、麦克风/语音权限 | Mac 真机测试，Windows 结果不替代 |
| Harness / VM / 外部模型 | 独立依赖或服务 | 按实际支持矩阵测，缺环境写阻塞 |

Mac 飞书移植至少包含：主进程/预加载桥平台分支、arm64/x64 官方 lark-cli 和 Node、
Mach-O 架构校验、冒号 PATH、tar.gz 单成员安全提取、执行权限、打包资源以及签名后验证。
`connectors/feishu/licenses/manifest.json` 已新增独立 darwin-arm64/x64 精确制品记录，
依据 `MAC_AUDIT.md` 的只读工程复核，包含 Mac 新增钥匙串模块通知和仅两项限定 MPL 例外。
这不是运行验收；不得继承 Windows 或另一架构批准，不得把 `.exe` 放进 `.app`。
平台支持须同时检查 renderer 的 useFeishu、preload、本机 host 与运行时，不能只移除一处判断。
签名会改变 Mach-O 字节，必须有签名前来源/哈希和签名后 Team ID/签名闭包检查，
不能让运行时按旧哈希误判已签名文件、转而偷偷依赖本机 PATH。
需真实 macOS 环境完成初次授权、IM、工具只读调用、退出/恢复和目录隔离；当前无该证据。

屏幕录制重复授权单列为 `mac-native-runtime-and-permissions` 的必需证据，不能只上传
codesign 成功输出：记录 macOS 版本、弹窗原文、频率、安装路径、签名 requirement、责任进程，
比较同版三轮操作/退出重开与覆盖升级。包内 embedded CUA 和已有 standalone CuaDriver 的
实际授权身份可能不同，必须记录真实模式；不能利用测试机器已有权限掩盖缺陷。
详见 [签名策略第 5.1 节](macOS代码签名与TCC身份策略.md#51-屏幕录制重复授权的定向诊断)；
同版权限循环或拒绝后无界重试阻断，系统自身周期性复核按原文与频率独立记录。

## 4.1 中文回复与提示词不回退

共用 `buildSystemPrompt` 固定加入“回复语言”段：用户说明、进度、结果默认简体中文，
明确请求其他语言/原文时例外，代码/命令/路径/工具名保持原样。不重写工作空间规则。
检查预览和实际发给 CLI/Harness 的提示词均含该段，再检查真实回复；单元断言不等于模型行为通过。
Harness 当前将 Bot 系统上下文与本轮请求合并传入 session；应以实际请求日志确认注入位置，
不能把它说成一定占用 Harness 原生最高优先级 system 字段。硬编码欢迎语不是模型提示词，单独验收。
覆盖单聊、群组、英文工具输出后的总结、会话恢复，不能靠写入某个 Bot 的私人 MEMORY 修复全局行为。
Harness 安全能力变化必须新开会话时，使用服务端受限 recoveryText 保留上下文；
不得取消凭据轮换，也不得在复用会话每轮重灌历史。

## 5. 机器执行的打包门禁

GitHub Actions 可先运行 `Ruijie pre-package verification (NO INSTALLERS)`：
文件为 `.github/workflows/verify-ruijie-prerelease.yml`，手工触发或推送到
`codex/verify-ruijie-*` 独立验证分支时触发，仓库权限只读。正式交付已归入 WYunS/main，
通常在 Actions 选择 main 执行并记录本次实际 SHA；验证分支仍可用于未合入的候选，不能混淆测试 SHA。
它分原生 arm64/x64 runner，执行源码、浏览器、打包形态服务端与模拟代理恢复测试；
不运行 electron-builder，不生成安装包、签名或发布，也不签发发布凭据。
本地修改必须先进入实际执行的验证分支；测试旧远程 SHA 不能验证本地新代码。
托管 runner 的通过不能替代飞书真实授权、TCC 人工权限和最终安装验收。

`electron-builder.ruijie.mjs` 的 `beforePack` 会读取
`release/verification/<win32-x64|darwin-arm64|darwin-x64>.json`，检查以下记录：

```json
{
  "schemaVersion": 1,
  "target": "win32-x64",
  "sourceFingerprint": "由指纹命令取得的实际 SHA256",
  "verifiedAt": "真实验收完成的 ISO 时间",
  "runtimeSha256": "实际测过并准备打包的 agent-browser SHA256",
  "connectedAppsBrokerUrl": "与实际发行配置相同并通过授权验收的 HTTPS 地址",
  "checks": {
    "source-regression": {
      "status": "blocked", "command": "实际执行命令",
      "evidence": "source-regression.log", "evidenceSha256": "日志文件的真实 SHA256"
    }
  }
}
```

必需检查名见脚本 `REQUIRED_RELEASE_CHECKS`；Windows 额外需要
`no-console-cold-start-and-restart`，Mac 额外需要 `mac-native-runtime-and-permissions`。
搜索路由与后台画面恢复分别必须有 `browser-search-routing-no-firecrawl`、
`browser-stream-background-recovery` 证据，不用零散单元测试代替真实工作流结果。
`reply-language-chinese` 须包含真实模型的普通回复、进度、继续任务，以及用户明确要求英文的例外；
提示词字符串存在不等于模型已经按中文回复。`connected-apps-proxy-recovery` 必须包含上述入口恢复流程。
必须全部 passed、有具体证据、目标一致、24 小时内、工作树和运行文件未变。
每项日志放在 `release/verification/` 内，记录命令和日志 SHA256；门禁会校验文件存在且未变。
缺证据就阻断，不提供 `--skip` 开关；不能删除 hook 或改用上游配置绕过。

```bash
node --test scripts/check-ruijie-release-readiness.node-test.mjs
node scripts/check-ruijie-release-readiness.mjs win32-x64
```

正常产物前缀所有平台均为 `RuijieBot`；内部 `.app`/appId 与签名身份仍按原策略保留。
预打包验证通过只允许生成候选。候选形成后还必须在独立账号安装，检查实际进程路径、
资源哈希、卸载名称、数据隔离、上述功能和签名，再确定最终安装包 SHA256 才能交付。
没有生成过的安装包无法提前做安装验收；不得把“预检通过”说成“安装版绝对没问题”。
