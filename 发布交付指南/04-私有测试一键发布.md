# 私有测试一键发布

本仓库是 `rj-liukaiwen/OpenMausBot` 的独立私有副本。公开仓库的 GitHub fork 不能单独设为私有，因此保留原 Git 历史后复制到独立私有仓库。

上游来源：`WYunS/OpenMausBot` 的 `codex/openmaus-upgrade-0.1.71-ready`，基准提交 `a9c8187712e6f99c8a63dadec2835c43dd982446`。首次测试版本为 **v0.1.73**。本指南描述此私有发布流程；01—03 及签名策略保留为上游验收基线。

## 下次如何发布

v0.1.73 首次交付已完成云端自动验收：[成功运行及 Artifacts](https://github.com/rj-liukaiwen/OpenMausBot/actions/runs/34554472677) · [私有 Release 草稿](https://github.com/rj-liukaiwen/OpenMausBot/releases/tag/untagged-bbbc55a55c3d583dd24b)。三个平台共同构建提交为 `585534fdd382b9470a77bcdd9c3c410cc21bb38a`。实体机安装与 TCC 验收仍待执行。

1. 将准备测试的代码提交到本仓库中包含新工作流的分支。
2. 打开仓库 **Actions → Private evaluation release → Run workflow**。
3. 选择分支，填写新版本号，例如 `v0.1.74`。`source_ref` 通常留空。
4. 选择 `release_mode`：`draft` 生成完整草稿；`prerelease` 发布为本私有仓库的测试版；`artifacts` 只生成 Actions 下载包。
5. 点击 **Run workflow**，等待所有作业完成。运行页底部 **Artifacts** 按平台下载，或从作业摘要打开 Release。

版本号只接受三段数字，可带 `v` 前缀。已经存在的标签或 Release 不会被覆盖。准备作业自动更新实际 `package.json` 版本并在 `evaluation/v版本/运行号-尝试号` 分支保存构建提交；所有平台都检出这一个完整 SHA。无需手工改安装包文件名，也不会把构建中的更改推到默认分支。

## 平台和签名

| 平台 | 产物 | 状态 |
| --- | --- | --- |
| Windows x64 | NSIS EXE、便携 ZIP | 未签名，不伪造 publisherName；可能有系统信誉提示 |
| Linux x64 | DEB、AppImage | 按 Ubuntu 24.04 测试；AppImage 下载后可能需要赋予执行权限 |
| macOS Universal | 一个 DMG、一个 ZIP，支持 Intel 与 Apple Silicon | ad-hoc signed, not notarized；没有 Developer ID 和 Apple 公证 |

应用身份保留 `com.openmausbot.app`、`OpenMausBot.app` 和安装版数据目录。Mac 合并 Electron、CUA SDK、cloudflared 等共用原生代码；内置浏览器完整保留两套对应架构资源并按运行架构选择。最终签名后不再修改应用内容，DMG 挂载后重新验签。签名审计会列出实际 Mach-O、嵌套 bundle、架构与 designated requirement。

Mac 的签名、公证和系统允许启动是不同检查。此工作流不使用 Apple 凭据、不声称通过公证，也不会关闭 Gatekeeper/SIP、删除 quarantine 或重置 TCC。换成 Developer ID 公证分发需要单独接入发行者证书和公证凭据。

## 自动执行的检查

- 锁文件安装、类型检查、打包配置检查、浏览器相关回归及隔离的打包服务器检查。
- 真实 Windows 和 Linux 运行器打包；Linux 包结构、安装／升级及运行 smoke。
- Apple Silicon 上构建 Universal，检查完整原生签名，并挂载最终 DMG 重验；Intel 运行器下载同一 ZIP，再做签名、浏览器与打包服务器验证。
- 检查包内更新目标、版本、关键资源。三个平台的报告必须具有相同版本与构建 SHA。
- 只上传明确列出的安装包、归档、更新元数据、校验和和构建报告。发布前重算实际 SHA-256/SHA-512，核对更新 feed，检查 GitHub 上传后的大小和可用 digest。
- 任一必需检查失败，停止组装 Release。此前已成功平台的 Artifact 仍可用于排错，不能视为三平台交付完成。

实体 Mac 上的首次安装、系统权限、TCC 稳定性、真实 Harness 账号及覆盖升级仍按 `03-macOS真人验收测试指导.md` 执行。Actions 临时系统不能证明这些项目通过。首次云构建状态及尚未验证项见 `docs/verification/private-release-0.1.73.md`。

## 私有仓库、更新与许可

工作流仅使用 GitHub 自动提供的 `GITHUB_TOKEN`，写权限限于准备和发布作业；普通构建作业只有读取权限。不需要把个人 GitHub token 打入应用。仓库所有者需要启用 Actions，并具有可用的托管运行器额度。

安装包更新目标改为本私有仓库。当前应登录 GitHub 后下载新版本进行安装；应用内自动访问私有 Release 没有配置客户端认证，不能承诺自动升级可用。安装器不附带账户凭据。

`enterprise/LICENSE` 第 1 条允许开发、测试和评估，第 3 条禁止未经授权再分发。此工作流用于用户自己的私有测试，保留许可证及功能许可检查，不提供生产或对第三方分发授权。Harness 仍须独立安装，不包含在 Bot 安装器内。

原上游工作流移到 `.github/upstream-workflows/` 供参考；该目录不执行。唯一活动工作流 `.github/workflows/private-release.yml` 只有手动触发，不向上游、npm、镜像仓库或旧 Release 镜像发布。

## 关键文件

- `.github/workflows/private-release.yml`：一键入口及验证顺序。
- `electron-builder.testing.mjs`：私有更新目标与签名配置。
- `scripts/prepare-private-release.mjs`：版本、源码 SHA 与独立候选提交。
- `scripts/package-private-macos.mjs`、`scripts/private-macos-sign.mjs`：Universal 合并、签名与最终 DMG 验证。
- `scripts/private-release-assets.mjs`、`scripts/publish-private-release.mjs`：产物清单、哈希与私有 Release。

Artifacts 保留 14 天。需要长期保留的测试版本使用草稿或私有预发布 Release；同一个已发布版本的不同字节不能覆盖，改用新的版本号。
